# Architecture Overview

Prometheus is positioned as a **supervisory execution-intelligence and selection layer**.

The current prototype is intentionally narrow: SABRE O3 candidate generation over a limited set of IBM Quantum processors available through the IBM Quantum Free Tier. The broader architecture is designed to accommodate additional compilers and heterogeneous QPUs.

## Separation of responsibilities

**Candidate generation** answers:

> How can this logical workload be realized physically?

**Prometheus selection** answers:

> Which available realization is most suitable for the current hardware environment?

**Dispatch** answers:

> Which available processor should receive the selected execution?

The current prototype demonstrates these concepts within a limited IBM/SABRE environment. The intended architecture allows the candidate-generation and processor layers to expand independently.

## Multi-compiler direction

The candidate-generation layer is intended to become compiler-agnostic. SABRE O3 is the current experimental baseline; TKET and other compilation strategies are intended future integrations.

A future candidate pool could therefore contain multiple physically valid realizations generated by different compilation stacks. Prometheus would evaluate those candidates within a common hardware-aware execution-selection framework.

## Multi-QPU direction

The same workload can be assessed against multiple operational processors.

The current prototype demonstrates this across supported IBM Quantum processors. The longer-term architecture is intended to extend the same arbitration concept across multiple providers and processor technologies, including superconducting and trapped-ion systems.

Potential future providers include IBM Quantum, Quantinuum, IonQ, and others where suitable execution interfaces and hardware characterization are available.

## Important boundary

The public architecture describes the **systems abstraction**, not the proprietary decision mechanism.

The internal mathematical objective, feature construction, weighting, candidate-ranking logic, and detailed selection heuristics are outside the public demonstration boundary.
